# spike/relay-wireguard: relay reachable only over WireGuard (SIMULATION)

**What this is.** Kernel WireGuard (the module in the colima VM) between three containers on **one** docker host, a firewall on the
relay machine that admits the libp2p port only from the WireGuard interface, and two `agentnet serve` daemons on the host. It
exercises the *same properties* a Tailscale deployment relies on (relay reachable only over an encrypted overlay, static peers on
overlay addresses, port restricted to known peers) and AgentNet's behaviour on top.

**What this is NOT.** Not Tailscale (no coordination server, no ACL engine, no MagicDNS, no DERP relays, no key distribution), not
NAT traversal, not separate physical hosts, not a WAN. Do not cite it as a Tailscale or cross-machine result. Analysis, results and
the list of what a real run needs: `docs/network-simulations.md`.

## Topology

```
 docker bridge "underlay" an-wg-br0 172.29.70.0/24  (stands in for the internet; the only thing the machines share)
   an-wg-r 172.29.70.10   an-wg-a 172.29.70.21   an-wg-b 172.29.70.22   (an-wg-intruder 172.29.70.66, no key, only for experiment 4)
 WireGuard overlay 10.66.0.0/24 (UDP 51820, hub and spoke): R 10.66.0.1, A 10.66.0.2, B 10.66.0.3
   A and B have R as their only peer (AllowedIPs 10.66.0.1/32); R has A and B.
 machine = sidecar container (owns wg0 + iptables) + Logos Delivery node sharing its namespace (network_mode: service:<sidecar>)
   R: node announces --nat=extip:10.66.0.1, listens tcp/60000.  A, B: --staticnode=/ip4/10.66.0.1/tcp/60000/p2p/<R id>
 R firewall: INPUT DROP; tcp/60000 accepted only on wg0 from 10.66.0.2 and 10.66.0.3; tcp/60000 on the underlay dropped explicitly
 host: agentnet serve (A) -> 127.0.0.1:28651 (A's node REST), agentnet serve (B) -> 127.0.0.1:28652, R's REST on 127.0.0.1:28650 (diagnostics)
```

REST ports are published to the docker host's 127.0.0.1 only so that the daemons on the host can reach them. In a real deployment each
agent runs next to its own node (loopback), exactly as `docs/relay-setup.md` says. The REST connections between the host and the nodes
are cleartext on the docker bridge (visible in the captures, and excluded from the "only WireGuard" counts for that reason).

## Run

```
cargo build --release --locked -p agentnet-cli -p agentnet-acceptance        # once, from the repo root
spike/relay-wireguard/run.sh                                                  # about 15-40 min, results/network-sim/wireguard/<UTC timestamp>/
BIN_DIR=/path/to/target/release spike/relay-wireguard/run.sh                  # use binaries built elsewhere
STEPS="1 2 3" spike/relay-wireguard/run.sh     # subset; KEEP_UP=1 leaves the containers; KEEP_RUN=1 keeps .run/
```

Idempotent: it removes any earlier `an-wg` project first, and removes its containers, network, volume and key files on exit.
Needs docker, standalone `docker-compose`, colima (`colima ssh -- sudo modprobe wireguard` is run for you), jq, curl, python3, openssl, perl.
It builds the small `an-net-tools:local` image (alpine + wireguard-tools, iptables, conntrack, tcpdump, nc; `image/Dockerfile`) if missing and
touches only containers/networks/volumes named `an-wg*` and the `an-wg-cap-*` capture containers.

Keys: WireGuard key pairs and libp2p nodekeys are generated by `scripts/gen-keys.sh` into `.run/` (gitignored, mode 600) for each run and
deleted on exit. They are disposable and never committed.
