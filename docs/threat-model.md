# AgentNet threat model

Status: first version, written by a contributor after the Phase A spikes and the Phase B MVP, for the owner to
fact-check; updated after the owner's conditions on ADR 0002 (rotation/revocation, rollback guard, downgrade
protection; see `docs/crypto-requirements.md`). Nothing here has been reviewed by an independent security reviewer.
The cryptographic scheme is a profile of RFC 9580 OpenPGP (`docs/adr/0004-openpgp-message-protection.md`, which
superseded ADR 0002's HPKE + Ed25519 composition) implemented by `sequoia-openpgp` 2.5.0 with the OpenSSL 3 backend;
the threat rows below were restated for it. The scheme and the glue are **unaudited**, have **no forward secrecy**
(none against a later compromise of a recipient encryption subkey), and must not be used in production for sensitive information before an
independent cryptographic review.

Evidence convention: a path with `:line` is source code in this repository at the time of writing (line numbers
drift; the symbol or test name is the durable reference). `results/...` paths are raw logs. **UNTESTED** means no
run in this repository exercises the statement. Everything that was run was run on **one macOS arm64 host**
(containers on a colima VM), see `docs/spike-report.md` section 2. Nothing in this document is a claim about
cross-machine, NAT, Tailscale or public-network behaviour. Simulated on one host (WireGuard overlay, MASQUERADE LANs): `docs/network-simulations.md`. Run once on two real hosts over an SSH tunnel (`results/cross-machine/20261126T190328Z/`) and once over a real tailnet (`results/tailscale-cross-machine/20261126T192147Z/`). On a tailnet deployment the tested access control is the relay host's firewall; the tailnet ACL was not tested, and the relay cannot tell which tailnet device a connection comes from. Message confidentiality and sender authentication come from AgentNet's own cryptography, not from the tailnet. Tailnet policy was tested as a reachability control on a Headscale tailnet (`results/tailnet-acl/20261126T215842Z/`): a member admitted by policy, or by a mistaken grant, can subscribe to topics and query the Store, so end-to-end encryption and the peer allowlist remain the controls; a revoked device lost connectivity within seconds; whoever administers the policy (the control server, hosted or self-hosted) is a trusted party for who may reach the relay. Raw libp2p over the public internet, NAT traversal, tailnet ACLs and key expiry remain UNTESTED.

Related: wire protocol `docs/protocol.md` (section 7 lists the security properties and non-properties),
architecture `docs/architecture.md`, host integration `docs/host-integration.md`, MCP surface `docs/mcp-api.md`,
configuration `docs/configuration.md`, relay deployment `docs/relay-setup.md`, dependency inventory
`docs/dependency-audit.md`.

## 1. Assets

| # | Asset | Where it lives | Why it matters |
|---|---|---|---|
| A1 | Ed25519 primary key of the OpenPGP certificate (the address is its fingerprint) | `<data_dir>/identity.json`, process memory | Loss of secrecy = impersonation until peers learn of a key revocation (`docs/protocol.md` section 9.5); there is no global revocation list |
| A2 | X25519 encryption subkeys (current and retained retired ones) | `identity.json`, process memory | Decrypts every recorded frame sealed to them, past and (until rotation) future |
| A3 | Message plaintext (bodies, ids, sender, type, conversation) | SQLite `agentnet.db` (plaintext, not encrypted at rest), process memory | Confidentiality of agent conversations |
| A4 | Contact book and trust decisions | `agentnet.db` | Controls who is acked, who can match triggers, who is quarantined |
| A5 | Control-socket token, HTTP MCP bearer token, webhook HMAC secret | `control.token`, `mcp-http.token`, `webhook.secret_file` (mode 0600) | Grant API access, MCP access, or the ability to forge webhook calls |
| A6 | Host event stream and trigger configuration | `agentnet.db`, config | Controls whether a harness spends compute on a message |
| A7 | Availability of delivery (relay, store, local node) | Operator infrastructure | Offline delivery depends on it |
| A8 | Metadata: who talks to which bucket, when, how much | Visible to relays, store nodes, network observers | See section 4 |
| A9 | Private-mode isolation (no contact with public Waku infrastructure) | Operator flags + AgentNet audit | Core promise of private mode |

## 2. Trust boundaries and actors

```
 [remote agent] --(sealed frame)--> [Logos Delivery relay/store] <--libp2p--> [local node sidecar]
                                         ^   ^                                      |
                           network observer   operator of relay/store              REST (no auth)
                                                                                    |
 [MCP host/client] --stdio/HTTP--> [agentnet mcp / http] --unix socket+token--> [agentnet serve daemon: identity, SQLite]
 [harness] --unix socket+token / signed webhook-->  daemon
 [Tailscale coordination plane] sees machine-level metadata only if tailnet is used (UNTESTED here)
```

| Boundary / actor | Trusted for | Not trusted for |
|---|---|---|
| **Agent host (OS user running the daemon)** | Everything. Holds A1-A5 in plaintext | Nothing is defended against it: **a compromised execution host is total loss** (section 5, T20). No confidentiality claim against it |
| **Daemon (`agentnet serve`)** | Single writer of identity and SQLite (exclusive lock `crates/daemon/src/datadir.rs`) | |
| **Local node sidecar (Logos Delivery node)** | Carrying opaque frames; reporting its own peer list | Confidentiality of what it carries (it sees only ciphertext + topic), honesty of its answers (a malicious local node can drop, replay or fabricate frames; fabricated frames fail authentication) |
| **Node REST API** | Nothing: it has **no authentication or TLS** (`docs/spike/notes-daemon-rest.md` s1.1, item 4 of s3). Must be loopback/private (T11) | |
| **Relay and Store operators** | Availability, retention | Anything else. They see section 4 metadata and can drop, delay, duplicate, reorder and replay frames |
| **Network observers** | | See section 4 metadata (IP, timing, size of the libp2p connection; payload is ciphertext) |
| **Tailscale coordination service** | Machine-level connectivity and ACLs (if used, **UNTESTED**) | Application identity and message encryption; it can observe which machines talk to which |
| **MCP host/client (stdio)** | Whatever it launches as the same OS user | Content of remote messages (untrusted data) |
| **MCP HTTP client** | Holders of the static bearer token | Browsers on the same machine (DNS rebinding, T15) |
| **Harness** | Decides whether to run inference; holds the control token | |
| **Remote agents (contacts)** | Authenticated as the holder of their address key | Their content (untrusted data, never instructions); their availability |
| **Unknown/untrusted senders** | | Quarantined by default |

## 3. Adversaries and capabilities

| ID | Adversary | Assumed capabilities |
|---|---|---|
| ADV1 | Passive network observer on the path to the relay or on the relay's network | Sees IPs, ports, timing, sizes of libp2p connections |
| ADV2 | Honest-but-curious or malicious relay/store operator | Sees every frame on every topic it carries, per-topic subscriber and publisher peer IDs and IPs, timing, padded size; can drop, delay, duplicate, replay, reorder; can retain forever |
| ADV3 | Another participant on the same relay/cluster (knows or guesses the cluster id, can reach the relay port) | Can join the gossipsub mesh, subscribe to any bucket topic, publish arbitrary frames to any topic, flood |
| ADV4 | Malicious or compromised contact (a trusted sender) | Sends authenticated messages with hostile content, floods, retries |
| ADV5 | Unknown sender who learned a victim's contact record | Can seal valid frames to the victim; sender identity is theirs, not the victim's contacts' |
| ADV6 | Local unprivileged user on the same machine (not the agent's OS user) | Can reach loopback TCP ports (node REST, HTTP MCP), can try to read files if modes are wrong |
| ADV7 | Web page in the user's browser | Can issue requests to loopback ports (DNS rebinding, cross-origin) |
| ADV8 | Attacker with read access to a disk backup or discarded disk | Reads `identity.json`, `agentnet.db`, tokens |
| ADV9 | Supply-chain attacker (a crate, the node image) | Controls code that runs with the daemon's or node's privileges |
| ADV10 | Compromised execution host / same-OS-user malware | Total access to A1-A6. **Out of scope: no defence is claimed** |

## 4. What each party can see (metadata)

Evidence: `results/a2-e2e-crypto/metadata-1795640646489.json`, section 8 of `docs/spike/notes-e2e-crypto.md`.
These were observed on the single-host topology. Publisher IP as seen by the first-hop node: **UNTESTED**.

| Observer | Sees | Does not see |
|---|---|---|
| Relay / Store node (stores and relays frames) | pubsub topic (`/waku/2/rs/66/0`), content topic = the recipient's **inbox bucket** (`/agentnet/1/inbox-<hh>/proto`, 1 of 16, stable per recipient), publish time (publisher clock, ns), payload length (`564` B for bodies of 1 B and 115 B in one run, `1076` B for 166 B: power-of-two buckets), the fact that the payload is an OpenPGP v6 SEIPD v2 (AES-256, OCB) message with an anonymous v6 PKESK (no key id or fingerprint; the ephemeral public key and wrapped session key look random), message hash, the peer ID (and IP) of the publishing node and of every subscriber of the topic | Envelope `v`, `message_id`, sender, recipient, `type`, `conversation_id`, `correlation_id`, `created_at`, `expires_at`, body, inner signature, body length inside a bucket |
| Any subscriber to the same bucket topic | All frames of the bucket; can trial-decrypt only its own | Content of others' frames |
| Network observer | Connection endpoints and timing; payload is ciphertext | Content |
| Tailscale coordination plane (if used; **UNTESTED**) | Which machines are in the tailnet, when they are online, connection metadata of the coordination protocol | Frame content, and (it does not terminate) the libp2p payload |

Properties and costs of the bucket scheme:

* **k-anonymity is within the bucket population of one deployment.** Bucket = `u16_be(fingerprint[0..2]) mod 16`
  (`docs/protocol.md` section 3). Anyone who knows an address can compute its bucket, so the scheme hides *which member of a bucket*
  a frame is for, not *which bucket*. With a small deployment (the 2-agent topologies used here) the anonymity set is 1-2.
* **Bandwidth/CPU trade-off, measured for the retired scheme.** The figures below were measured on the HPKE implementation of ADR 0002 (before 2026-11-26) and were **not re-measured for the OpenPGP scheme** (UNTESTED there; the cost is the same order: one X25519 operation per candidate subkey per frame, `docs/spike/notes-openpgp.md`). A foreign frame costs one X25519 decapsulation + AEAD failure per receiver in the bucket:
  **52.5 / 54.3 / 58.7 us** best-batch (three runs, 10 000 ops each, host macOS arm64, release build, host heavily loaded; median-batch
  63.9 / 71.2 / 117.1 us) per failed open (`results/a2-e2e-crypto/bench-standalone-{1,2,3}.txt`, `docs/spike/notes-e2e-crypto.md` s7).
  A successful full open incl. Ed25519 verify: 97.1-102.0 us best-batch. In the 100-logical-client / 1000-message run with 16 buckets,
  **6695 failed trial decryptions** were observed for 1000 delivered messages, i.e. 6.7 foreign frames processed per delivered message
  (`results/a2-e2e-crypto/load-1795640646489.json`, row "100 clients, poll 50 ms"). Arithmetic from the measured 55 us: 1000 foreign frames/s in one bucket
  is about 5.5 % of one core (derived, not separately measured). More buckets means fewer foreign frames per agent and a smaller anonymity set; fewer buckets the reverse.
  The bucket count (16) is a protocol constant.
* **Store catch-up** replays every frame of the bucket inside the requested window (up to `storage.retention_hours`, default 168), so recovery bandwidth also scales with bucket population (not measured beyond the 20-message test, `results/a1-daemon/rust-probe-offline-45d196c.json`).
* Timing correlation (sender publishes at t, recipient's bucket sees a frame at t) is **not mitigated**. No cover traffic, no mixnet. Mixnet readiness is **not claimed**.

## 5. Threats, mitigations implemented, residual risk

Mitigation column cites code or tests. "Residual" is what remains after the mitigation.

### 5.1 Message security

| # | Threat | Mitigation implemented | Evidence | Residual risk |
|---|---|---|---|---|
| T1 | Passive/active party reads a message (confidentiality) | OpenPGP PKESK v6 (X25519) + SEIPD v2 (AES-256, OCB), anonymous recipient, per-message ephemeral key, salt and session key; trusted to the library, not reviewed | `round_trip_all_message_types`, RFC 9580 vectors (`vectors.rs`) | Library risk (Sequoia, OpenSSL: not audited at the pinned versions; both shipped security fixes in Nov 2026); metadata in section 4 |
| T2 | Later compromise of a recipient encryption subkey decrypts recorded history (no forward secrecy / PCS) | `rotate-kem` limits *future* exposure; `--revoke-previous` destroys earlier subkey secrets; retired subkeys are destroyed after `retire_at` (`prune_retired`) | `rotation_publishes_a_new_subkey_and_keeps_old_messages_readable_until_retire_time`, `identity.rs` tests | **Accepted, unchanged:** frames already recorded and sealed to a still-held or leaked subkey stay readable; no PCS; transferable signatures (no deniability) |
| T3 | Forged sender (impersonation of a contact) | The inner OpenPGP v6 Ed25519 signature (made by the sender's primary key) is verified over the signed payload, under the certificate whose fingerprint is the `sender` address (pinned, or for an unknown sender the embedded one, T35c) | `forged_sender_is_bad_signature`; spike `forgery-1795640646489.json` (forged sender -> `bad_signature` 1/1, honest control opened) | Holder of a contact's signing key can impersonate them to everyone; no revocation (T22) |
| T4 | Message redirected to a different recipient (surreptitious forwarding) | The signature carries the Intended Recipient Fingerprint of the recipient's primary key and the receiver REQUIRES it (both libraries accept signatures without it; found by the spike); the payload `recipient` is cross-checked too | `surreptitious_forwarding_is_rejected_by_the_intended_recipient`, `a_signature_without_intended_recipient_is_rejected_even_when_forwarded`, `engine_openpgp_regressions.rs` | The check is application code (security-critical, for the review); the subpacket is non-critical as Sequoia emits it |
| T5 | Tampering / truncation / extension | AEAD tag + header in `aad`; strict length-prefix and zero-padding check | `every_single_bit_flip_is_rejected` (564-byte frame: 4512 single-bit flips rejected: 32+256+4096+128), `truncation_at_every_length_is_rejected`; spike `tamper-1795640646489.json` | None known |
| T6 | Replay of a valid frame | Persisted `(sender, message_id)` set until `expires_at + clock_skew`; `open` rejects expired envelopes; `transport_seen` is only an optimisation; replay guard after a store rollback / unknown history / identity import (T30) | `replay_now_and_after_dedupe_pruning`, `replay_after_restart_is_rejected`, `rollback_enters_the_replay_guard_and_holds_replayed_frames`, `migration_guard_by_default_and_full_state_copy_keeps_history`; table in `docs/protocol.md` s10 | A replay inside the TTL of a message whose dedupe row was lost (rollback without sidecar protection, `--no-replay-guard`, deleting the sidecar and database together); the same identity in two data dirs has independent dedupe (T23); clock errors (T21). A **duplicate re-triggers an ack** (at most once per `reack_min_interval_s` = 30), which an attacker holding a recorded frame can use to make the victim publish acks (small amplification, bounded) |
| T7 | Malformed input crashes the parser | Total, strict parsers; property tests (`prop_open_never_panics_on_arbitrary_bytes`, `prop_authentic_garbage_envelope_never_panics`, `ten_thousand_random_frames_never_panic`) | `results/b-core/crypto-tests.log` | **No coverage-guided fuzzing was run** (goal.md section 5 asks "if feasible"): UNTESTED. Unknown `v`, suite, frame version are rejected with distinct errors |
| T8 | Weak/low-order public keys | The library validates keys (Sequoia 2.5.0 fixed an Ed25519 low-order key acceptance bug in this release line, `docs/spike/notes-openpgp.md` 2.5); contacts accept only v6 Ed25519/X25519 | contact parse tests | Relies on the library |
| T9 | Substituted contact certificate (wrong key for an address) | The address is the certificate's fingerprint; `add_contact` compares it with `expected_address` (`--expect`); updates are merges that must have the same primary key; subkeys need valid binding signatures, forged or stripped bindings add nothing | `a_stripped_or_forged_subkey_binding_is_refused`, `updates_are_merges_only_and_a_different_primary_is_refused` | First contact without `--expect` is TOFU; a thief of the primary key can bind any subkey |
| T10 | Hostile content tries to make the agent act (prompt injection) | Bodies are data. MCP tool and field descriptions state they are UNTRUSTED (`tool_descriptions_state_the_trust_and_delivery_semantics`); events carry references, never text; no tool executes remote content; remote senders cannot create triggers, change policy or set webhook targets | `crates/mcp/src/server.rs` descriptions; `crates/daemon/tests/webhook_triggers.rs` (`unauthorized_senders_never_produce_trigger_events`); `docs/host-integration.md` s0 | **This is not solved by AgentNet.** The model that reads `read_inbox` output can still be manipulated by an authenticated contact's text; a trusted contact is trusted to send text, not to command. Hosts must treat bodies as untrusted input. No content scanning exists |

### 5.2 Local node, network and private mode

| # | Threat | Mitigation implemented | Evidence | Residual risk |
|---|---|---|---|---|
| T11 | Unauthenticated node REST abused by a local attacker (ADV6) | Private mode refuses a `node_url` that is not loopback/RFC 1918/100.64.0.0/10/ULA; documentation says bind loopback only | `crates/transport/src/logos_rest/config.rs` (`validate`), `config::tests::private_mode_*`; `agentnet relay print-config` publishes REST on host loopback only | **Anyone who can reach the REST port controls the node.** With `--rest-admin=true` (required by the isolation audit and redial) they can dial arbitrary peers (`POST /admin/v1/peers`), list peers, read and **drain** the relay cache (every `GET` is destructive: loses live frames; Store catch-up still recovers within retention), unsubscribe topics (unsubscribing drops the node from the mesh, `unsub-experiment.txt`), and publish garbage. They cannot decrypt frames (T1) or forge senders (T3). The node REST has no authentication to add; mitigation is network placement only. Any non-agent user on the same host can reach loopback ports: **single-tenant hosts only** |
| T12 | Node connects to public peers while AgentNet believes it is private | (a) Startup validation: cluster id not in {1,2,3,16}, `peers` non-empty, `public_*` false (fail closed); (b) runtime audit of `GET /admin/v1/peers` every `audit_interval` (default **15 s**): any connected peer id outside the allowlist or an unauditable node (including a peer list with a malformed entry or an unrecognised `connected` state) -> `isolation_violation`, sends and receives refused; (b2) static/store peer multiaddrs in private mode must be one private IP literal + one `/p2p/` id (no `/p2p-circuit`, DNS or extra hops; node behaviour with such addresses UNTESTED); (c) redial POSTs only the configured static peers (rate limit 10 s); (d) `mode = "public"` skips the audit unless `enforce_peer_allowlist = true`, which runs the same audit with peers allowed as public IP / dns4 / dns6 + tcp + optional tls/ws/wss + one `/p2p/` (no relay hops): validated once against a real public-IP relay over raw tcp (`results/public-ip-relay/20261126T211443Z/`), wss/DNS endpoints with it **UNTESTED**; `doctor` reports `[skip] not audited in public mode` in plain public mode | `crates/transport/src/logos_rest/mod.rs` `fetch_audit`/`ensure_audit`/`redial`; `isolation_violation_blocks_everything_until_cleared`; live: `isolation_audit_passes_with_right_allowlist_and_fails_closed_with_wrong_one` (`results/b-transport/relay-tests.log`) | The audit is **detective, not preventive**: it reads the node's peer list, it cannot stop the node dialling. Status/receive paths may see a peer up to 15 s late, but every publish runs its own uncached audit first (fix for the race in `results/public-ip-relay/20261126T211443Z/`, check 3d), so the publish window is one REST round trip: a peer that connects between the audit response and the publish request can still receive that one message (HPKE-encrypted to the recipient; the node API has no atomic check). The fix passed 3 of 3 runs of a real-node test on the local relay (`results/audit-window/SUMMARY.md`); it was not re-run against a public relay. **Whether the node contacts public infrastructure depends on the operator's node flags** (discovery off, `--dns-addrs-name-server`, `--cluster-id`, `--nat=extip`, `--quic-support=false`); AgentNet cannot set them. The audit does not look at DNS: the node's default online-monitor queries `one.one.one.one` via 1.1.1.1 every 5 s even with all discovery off (E7, `results/a1-daemon/egress-default-dns.egress.txt`). With `--dns-addrs-name-server=127.0.0.1`: 1175 packets in 100 s, 0 with an endpoint outside the container subnet (`results/a1-daemon/e7b-egress-dns-localhost-run.txt`). Capture was on the colima VM bridge only; UPnP/PMP, QUIC: **UNTESTED** on the bridge. **Real-host egress notes:** a client node dialling a relay by DNS name needed a real resolver (1.1.1.1), so it sent the relay's hostname to a public resolver (metadata, and the zero-public-egress property does not hold for it); with the default `--nat=any` a client node behind a home router attempted UPnP/NAT-PMP mapping, avoided with `--nat=extip:<ip>` (`results/public-relay/20261126T203405Z/SUMMARY.md`, Deviations). The relay's public edge or firewall also sees the client's source IP and timing; the public-IP run's capture showed the client's public address as source with Noise on the wire (`results/public-ip-relay/20261126T204713Z/SUMMARY.md`) |
| T13 | Anyone who can reach the relay joins the private cluster | None in AgentNet. Cluster/shard separation is **not access control** (goal.md B2). Peer-ID allowlisting is **client-side**: a client ignores unknown peers' effect only by refusing to operate (T12); the *relay* accepts any peer that dials it and knows cluster 66 / shard 0 | `docs/spike/notes-daemon-rest.md` s1.2  With `enforce_peer_allowlist` the node's mesh membership is audited and an unlisted connected peer fails the transport closed (observed once on a real public-IP relay, `results/public-ip-relay/20261126T211443Z/`); a message sent inside the detection window can still leave the node. Plain public mode audits nothing. | **Unmitigated at the AgentNet layer.** Demonstrated: with the firewall rule removed an intruder with the right cluster id joined R, received live ciphertext frames and Store history (topics, sizes and timing visible, no plaintext). A joiner can subscribe to every bucket (sees ADV2-level metadata), publish garbage (T16), consume relay bandwidth. Needs firewall / tailnet ACL restricting tcp/60000 to known client IPs (`docs/relay-setup.md`). A relay on a public address with `enforce_peer_allowlist` is still open to strangers. **Demonstrated on a public endpoint:** behind a provider's wss/TLS edge, an uninvited node with a random key and the right cluster id joined and pulled 145 stored frames (uniform 564-byte ciphertext, topics and timing visible, 0 plaintext hits); REST was not reachable (`results/public-relay/20261126T203405Z/SUMMARY.md`, check 6). **Stateful firewall caveat:** on a public IP, removing the client's allow rule from a stateful cloud firewall did not cut the established flow; only new dials were blocked, so revoking a client also needs a relay or client restart (`results/public-ip-relay/20261126T204713Z/SUMMARY.md`, check 6; whether the relay kept a stale socket: UNTESTED); the setting only keeps *this* node from meshing with unlisted peers, and the node may use a public DNS resolver. No RLN on private clusters (`--rln-relay=false`): no rate limiting except `--rate-limit` (UNTESTED)  |
| T14 | Relay outage, restart or partition (availability) | Retry with jittered exponential backoff (2 s base, 5 min cap, `max_attempts` 20), Store catch-up at start/reconnect/every `history_sync_interval_s` (default 15 s), static-peer redial | `lost_publish_retries_with_backoff_bounds_then_delivers`, `offline_recipient_recovers_20_via_history`; live: redial 11.4 s (`results/b-transport/relay-disruptive-tests.log`) | After a relay restart the **gossipsub mesh took about 9 minutes** to carry live traffic again (E12, cause not found); recovery then relies on Store. Store availability, retention (`time:3600;capacity:5000` in the verified flag set = **1 hour**), and the +-20 s archive timestamp rule bound offline delivery. A relay operator can simply refuse to store. There is no automatic Store failover (E9). Separately, after a silent path loss the relay can keep a half-open TCP socket for about 22 minutes and refuse client redials; root cause and a relay-side mitigation (`tcp_retries2=6`) are in `results/reconnect/20261126T065412Z/SUMMARY.md` (single-host simulation; real networks UNTESTED) |
| T15 | Browser-based attack on loopback HTTP MCP (DNS rebinding / CSRF) | Static bearer required on every request (constant-time compare, minimum 16 bytes); `Host` allowlist (default `localhost`, `127.0.0.1`, `::1`); `Origin` validation always on (empty allow-list = any present Origin is 403); non-loopback bind refused | `crates/mcp/src/http.rs`; `http_auth_origin_and_host_rules`, `serve_http_refuses_unsafe_configuration`, `router_fails_closed_with_an_unusable_token` (`results/b-mcp/cargo-test.log`); config `mcp_http.bind` must be loopback (`config::tests::mcp_http_bind_must_be_loopback`) | A **static bearer is not the MCP OAuth profile** (`2026-07-28/basic/authorization`); a host that requires OAuth discovery cannot authenticate. The token lives in a 0600 file; any process of the same OS user can read it. Third-party MCP hosts (Claude Code, Inspector) **UNTESTED** |
| T16 | DoS: flooding a bucket topic or the store (ADV3, ADV5) | Foreign/garbage frames are rejected cheaply (one anonymous-PKESK trial decryption per candidate subkey: an X25519 operation, about 55 us measured for the retired HPKE scheme; **not re-measured for OpenPGP**, UNTESTED); `transport_seen` prunes after 24 h or above 200 000 rows (`TRANSPORT_SEEN_CAP`, `crates/core/src/node.rs:35`); inbound channel bounded (256) with back-pressure; inbox cap `max_inbox_records` (100 000), quarantine cap `max_quarantined` (1000), outbox cap `max_outbox_pending` (1000) | `inbound_channel_applies_backpressure_and_loses_nothing`, `inbox_saturation_not_acked_then_accepted_after_space_frees`, `outbox_saturation_returns_unavailable`, `reject_blocked_accept_untrusted_and_quarantine_cap` | **Every foreign frame costs a SQLite write**: `ingest_frame` calls `mark_transport_seen` for `NotForUs` (`crates/core/src/ingest.rs`, branch `OpenError::NotForUs`), with `synchronous=FULL` (`docs/protocol.md` s8.8). A flood of 10^5 distinct frames grows `transport_seen` to its cap and costs CPU+fsync; **no flood test was run**: UNTESTED. The relay has no rate limit without RLN (T13). A full inbox makes the daemon refuse (not ack) new messages from legitimate senders. The REST cache is 50 slots and destructive: a flood within one poll interval evicts legitimate live frames silently (Store catch-up recovers them if the relay archived them) |

## 7. Not claimed

* **Anonymity or unlinkability.** Relays and observers see bucket, timing, size and publisher/subscriber peer identity.
* **Mixnet readiness.** No evidence gathered.
* **Forward secrecy, post-compromise security, deniability.** (A forward-secret scheme is a documented upgrade path, `docs/crypto-interface.md`; none is implemented.)
* **A global directory, reputation or verified capabilities.** Optional discovery lists unverified, public claims seen on the local relay (`docs/discovery.md`).
* **Global or reliable revocation.** Revocation reaches only peers that receive the notice (`docs/protocol.md` s9.5).
* **Detection or prevention of the same identity running in two places.**
* **Recovery of messages lost to a store rollback.**
* **Protection against a compromised host, a malicious local user with the same UID, or a malicious node image.**
* **Production reliability.** All measurements are single-host, container networking, amd64 images under qemu on arm64, on a heavily shared machine (`docs/spike/notes-e2e-crypto.md` header).
* **Cross-machine, NAT and Tailscale behaviour.** UNTESTED; steps are in `docs/relay-setup.md`. Simulated on one host only (WireGuard overlay, MASQUERADE LANs): `docs/network-simulations.md`; real Tailscale, NAT and separate hosts remain UNTESTED.
* **Public network interoperability.** UNTESTED, deliberately.
* **A security audit.** None of the code or the cryptographic composition has been reviewed by anyone outside the project.
* **Resistance to flooding.** No flood or load test against hostile traffic was run (also for the optional discovery topics, T32).
* **Windows.** Not supported.

## 8. What a security review should look at first

Prioritised.

1. **The OpenPGP policy and glue** (`crates/core/src/crypto/`: `pgp.rs`, `protection.rs`, `contact.rs`, `revocation.rs`, `docs/protocol.md` s3-s5, s9-s10; the list is in ADR 0004, "What the independent cryptographic review would then cover"): the receiver policy, the mandatory Intended Recipient, certificate sanitize/merge, subkey selection and retention, the missing signature context, library choice and the C backend. The retired ADR 0002 scheme (HPKE base mode, the `hpke` crate, an AgentNet envelope signature) is no longer part of the system and is not a review item; it survives only in dated records and in the `identity migrate` path, which reads old identity files without using their keys.
2. **Key handling at rest and in memory** (`crypto/identity.rs`): plaintext 0600 file, zeroization limits, export format, retained retired encryption subkeys (`retire_at`).
3. **Identity migration / split brain** (T23) and the rollback guard (T30): decide whether a second-instance detection is required before any real use, and whether the sidecar scheme is sufficient.
4. **Private-mode isolation**: that the peer-allowlist audit and the config checks cover the real node flags; whether a *preventive* control (the operator's firewall egress rules) must be mandated; DNS egress behaviour on the target platforms.
5. **Ingest path under hostile load** (`crates/core/src/ingest.rs`, `node.rs`): `NotForUs` writes, `transport_seen` growth, SQLite fsync cost, inbox/quarantine saturation behaviour; run a flood test and fuzzers.
6. **Control socket and HTTP MCP authentication** (`server.rs`, `http.rs`): token handling, Host/Origin checks, behaviour with third-party hosts, whether the OAuth profile is needed.
7. **Webhook** (`webhook.rs`): SSRF controls with a real resolver, redirect and proxy handling, secret handling, replay protection contract.
8. **Trigger/wake logic** (`triggers.rs`): budgets, one-shot atomicity, `since_cursor` matching.
9. **Supply chain**: the dependency set (`docs/dependency-audit.md`), the node image's provenance and signature (not verified), root-in-container.
10. **Operational guidance**: the retention defaults in the verified relay flag set (1 hour) versus the client's 168 h expectation, clock requirements.
