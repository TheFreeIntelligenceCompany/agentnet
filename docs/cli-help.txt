===== agentnet  --help =====

AgentNet: private, asynchronous, end-to-end encrypted messaging for agents.

NOT AUDITED. The cryptography (HPKE + Ed25519, no forward secrecy) has had no independent review: an
independent cryptographic review is required before production use involving sensitive information.

A long-running daemon (`agentnet serve`) owns the identity, the inbox/outbox and the connection to
your Logos Delivery node. Every other command talks to that daemon over its control socket, except
the few that manage the data directory while no daemon runs (`init`, `identity
export|import|rotate-kem|revoke`).

Usage: agentnet [OPTIONS] <COMMAND>

Commands:
  init        Create a data directory with a new identity, a private-mode config and access tokens
  serve       Run the daemon in the foreground until Ctrl-C or SIGTERM
  mcp         Serve MCP over stdio as a thin client of the running daemon
  identity    Show, export, import and rotate the identity (daemon must be stopped for all but
              `show`)
  contact     Manage contacts (verified peer records)
  quarantine  Inspect and release messages from unknown or untrusted senders
  send        Send a message to a contact
  inbox       Read received messages (cursor-paginated, oldest first)
  ack         Mark a received message as processed locally (idempotent; unrelated to the delivery
              receipt)
  status      Show the delivery state of a sent message (queued, sent, delivered, failed, expired)
  outbox      List sent messages and their delivery state
  trigger     Manage triggers: durable predicates that turn matching inbound messages into events
  events      Follow the host-integration event stream
  discovery   Optional capability discovery: advertise this agent, withdraw, list others
  network     Network and queue status
  doctor      Check permissions, config, node reachability, peer allowlist, isolation, store and
              clock
  relay       Instructions for running your own relay/store node
  help        Print this message or the help of the given subcommand(s)

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --json
          Print machine-readable JSON instead of human text

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

EXIT CODES:
  0  success
  1  other error (I/O, internal, a second daemon on the same data dir, ...)
  2  usage error (bad command line)
  3  the daemon or the network node is unavailable (is `agentnet serve` running?)
  4  invalid argument or invalid configuration
  5  not found
  6  refused by policy (also: too large, conflict)
  7  `agentnet doctor` found at least one failing check

The data directory defaults to $AGENTNET_HOME, then ~/.agentnet. Logs go to
stderr (RUST_LOG controls the level, default `warn`); stdout carries only
command output (and, for `agentnet mcp`, MCP protocol frames).

===== agentnet doctor --help =====

Check permissions, config, node reachability, peer allowlist, isolation, store and clock.

Prints an actionable line per check; exits 7 if any check fails. Also reports the replay guard
(after a store rollback, an unknown store history or an identity import) and whether the identity is
revoked.

Usage: agentnet doctor [OPTIONS]

Options:
      --accept-rollback
          Accept a detected store rollback / unknown history / import so the next start does not
          hold older messages, and release the held ones. Requires the daemon to be stopped.
          Messages that were received and acknowledged before the rollback cannot be recovered, and
          frames replayed from before the rollback are accepted again within their TTL

      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --json
          Print machine-readable JSON instead of human text

===== agentnet identity rotate-kem --help =====

Generate a new agreement (KEM) key and increment the key epoch; the address stays the same.

By default the previous key keeps decrypting until the retention window ends. At the next `agentnet
serve` the new signed record is sent to every Trusted contact as a `contact.update`, and their
pending messages to you are re-sealed to the new key. With --revoke-previous all earlier KEM keys
are destroyed at once: messages already sealed to them are lost unless re-sealed by their senders
after they learn the new record.

Usage: agentnet identity rotate-kem [OPTIONS]

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --keep-hours <HOURS>
          How long the previous key keeps decrypting (default: storage.retention_hours)

      --json
          Print machine-readable JSON instead of human text

      --revoke-previous
          Destroy every earlier KEM key immediately and publish `revoked_kem_epochs_below`

  -h, --help
          Print help (see a summary with '-h')

===== agentnet identity revoke --help =====

Revoke this identity (the signing key): irreversible for this address.

Writes a signed tombstone next to the identity and marks the local identity revoked: the daemon then
sends nothing except the tombstone, which it delivers to every Trusted contact at the next start.
Reaches only contacts that are reachable within the TTL/retry limits or that receive the document
out of band (`identity show-revocation`). There is no global revocation list; a thief of the signing
key can also issue a tombstone (denial of service only).

Usage: agentnet identity revoke [OPTIONS] --reason <TEXT>

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --reason <TEXT>
          Why (1-256 bytes, no control characters); shown to contacts

      --json
          Print machine-readable JSON instead of human text

  -h, --help
          Print help (see a summary with '-h')
