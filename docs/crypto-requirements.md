# Owner conditions: status under ADR 0004

The repository owner accepted HPKE + Ed25519 for the MVP on 2026-11-25 subject to
13 conditions (`docs/adr/0002-end-to-end-encryption.md`). On 2026-11-26 the owner
ruled that construction hand-rolled at the protocol level and accepted
**RFC 9580 OpenPGP with `sequoia-openpgp` 2.5.0 (OpenSSL 3 backend)**
(`docs/adr/0004-openpgp-message-protection.md`); ADR 0002 is superseded and its code is
removed (hard cutover). The 13 conditions were written for ADR 0002. This table
restates each against ADR 0004: which are now met by the standard or the library,
which remain ours, which no longer apply. "Met" means the stated mechanism is
implemented and tested, **not** that the design or the library has been reviewed.
Nothing here has been independently audited; the implementation is **not audited,
not production-secure and not forward-secret** (no forward secrecy against later
compromise of a recipient encryption subkey).

Test locations: `core/tests/crypto.rs`, `core/tests/vectors.rs`,
`core/tests/engine_security.rs`, `core/tests/engine_openpgp_regressions.rs`,
`core/tests/engine_hardening.rs`, `core/tests/review_crypto.rs`, `core/tests/review_engine.rs`, `core/tests/migration.rs`,
`core/tests/architecture.rs`, `daemon/tests/migrate.rs`,
`daemon/tests/rotation_revocation.rs`, `cli/tests/cli.rs`.

## External automated review

`results/review/codex-astra-review.md` and `results/review/codex-astra-usability-review.md` were model-run reviews of the ADR 0002 code. They are **not** the independent human cryptographic review of condition 11, which remains **Not met**, and their findings were about code that no longer exists (the stale-frame, replay-guard and engine protections they led to are kept).

## What is deliberately not done

* No AgentNet-defined cryptographic construction remains: no KDF, no signing prefix, no envelope-binding scheme, no key-epoch scheme. What remains ours is policy and glue (section 6 of `docs/spike/notes-openpgp.md`), listed for the reviewer in ADR 0004.
* No detection of the same identity running twice (unsound; documented).
* No forward-secret scheme (documented prerequisites only).
* No `agentnet state export/import`: full-state migration is the documented copy of `agentnet.db` and `agentnet.generation` with the daemon stopped.
* The RFC 9580 Intended Recipient subpacket is required on receive but not marked critical on send (Sequoia sets it non-critical; RFC 5.2.3.36 says SHOULD be critical for v6): UNTESTED interoperability consequence.
