134:### E12 reconnect after relay restart needs an explicit dial (`results/b-transport/relay-disruptive-tests.log`)
146:5. REST receive = destructive-read in-memory cache of 50 messages (configurable), shared by all topics; overflow drops oldest silently, returns out-of-order, loses everything on restart; a static-pubsub subscription caches every content topic on the shard; publishers see their own messages. A durable adapter must poll fast (or raise capacity), persist what it reads, and treat Store as the recovery path.
170:Path (3) is workable with the pinned amd64 image: private cluster, static peers, relay + store + filter + lightpush all functioned with no RLN and one controlled public-contact leak that is removable by flag. The REST receive model is the weak point (volatile 50-slot destructive cache, no hashes, self-echo); the `/messaging/v1` layer addresses hashes/history/send status but is unstable across versions and was only smoke-tested. Any confidentiality, sender authentication and replay protection are absent at this layer and must come from the application protocol.
