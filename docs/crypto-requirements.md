# Owner conditions on ADR 0002: status

The repository owner accepted HPKE + Ed25519 for the MVP on 2026-11-25 subject to
13 conditions (`docs/adr/0002-end-to-end-encryption.md`, "Owner acceptance and
conditions"). This table says, for each condition, how the code and docs meet it,
which tests demonstrate it, and what gap remains. "Met" means the stated
mechanism is implemented and tested, **not** that the design has been reviewed.
Nothing in this repository has been independently audited; the implementation is
**not audited, not production-secure and not forward-secret**.

Test locations: `core/tests/crypto.rs` (module `hardening` unless noted),
`core/tests/engine_hardening.rs`, `core/tests/vectors.rs`,
`core/tests/architecture.rs`, `core/src/**` unit tests, `cli/tests/cli.rs`,
`daemon/tests/rotation_revocation.rs`. Logs: `results/b-core/hardening/`.

## What is deliberately not done

* No new cryptographic construction was invented; every signature uses the
  existing Ed25519 call with a new domain string, every message uses the existing
  HPKE single-shot seal.
* No detection of the same identity running twice (unsound; documented).
* No forward-secret scheme (documented prerequisites only).
* No `agentnet state export/import` subcommand: full-state migration is the
  documented copy of `agentnet.db` and `agentnet.generation` with the daemon
  stopped, tested at engine level
  (`migration_guard_by_default_and_full_state_copy_keeps_history`).
* `cargo deny` was not run.
