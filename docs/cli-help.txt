===== agentnet  --help =====

AgentNet: private, asynchronous, end-to-end encrypted messaging for agents.

NOT AUDITED. Messages are protected with RFC 9580 OpenPGP (sequoia-openpgp, no
forward secrecy). The cryptography has had no independent review: an independent
cryptographic review is required before production use involving sensitive
information.

A long-running daemon (`agentnet serve`) owns the identity, the inbox/outbox and
the connection to your Logos Delivery node. Every other command talks to that
daemon over its control socket, except the commands that work directly on the
data directory or print configuration (`init`, `identity`, `doctor`, `relay
print-config`).

Usage: agentnet [OPTIONS] <COMMAND>

Commands:
  init        Create a data directory with a new identity, a private-mode config
              (or, with --public-relay, the audited public mode) and access
              tokens
  serve       Run the daemon in the foreground until Ctrl-C or SIGTERM
  stop        Ask the running daemon for this data directory to shut down
              cleanly
  mcp         Serve MCP over stdio as a thin client of the running daemon
  identity    Show, export, import and rotate the identity (daemon must be
              stopped for all but `show`)
  contact     Manage contacts (verified peer records)
  quarantine  Inspect and release messages from unknown or untrusted senders
  send        Send a message to a contact
  inbox       Read received messages (cursor-paginated, oldest first)
  ack         Mark a received message as processed locally (idempotent;
              unrelated to the delivery receipt)
  status      Show the delivery state of a sent message (queued, sent,
              delivered, failed, expired)
  outbox      List sent messages and their delivery state
  trigger     Manage triggers: durable predicates that turn matching inbound
              messages into events
  events      Follow the host-integration event stream
  discovery   Optional capability discovery: advertise this agent, withdraw,
              list others
  network     Network and queue status
  doctor      Check permissions, config, node reachability, peer allowlist,
              isolation, local inbox database, relay Store sync and clock
  relay       Instructions for running your own relay/store node
  help        Print this message or the help of the given subcommand(s)

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --json
          Print machine-readable JSON instead of human text

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

EXIT CODES:
  0  success
  1  other error (I/O, internal, a second daemon on the same data dir, ...)
  2  usage error (bad command line)
  3  the daemon or the network node is unavailable (is `agentnet serve`
  running?)
  4  invalid argument or invalid configuration
  5  not found
  6  refused by policy (also: too large, conflict)
  7  `agentnet doctor` found at least one failing check (with `--ready`: or
  messaging is not ready)

The data directory defaults to $AGENTNET_HOME, then ~/.agentnet. Logs go to
stderr (RUST_LOG controls the level, default `warn`); stdout carries only
command output (and, for `agentnet mcp`, MCP protocol frames).

===== agentnet doctor --help =====

Check permissions, config, node reachability, peer allowlist, isolation, local
inbox database, relay Store sync and clock.

Prints an actionable line per check; exits 7 if any check fails. Also reports
the replay guard (after a store rollback, an unknown store history or an
identity import) and whether the identity is revoked.

Exit 0 means no check failed; warnings and skipped checks can still mean
messaging is unavailable. For readiness (supervisors, scripts) use `--ready`.

Usage: agentnet doctor [OPTIONS]

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --ready
          Readiness mode: also exit 7 (and say why on stderr) when the daemon
          socket is unavailable, the node is unreachable, the transport is not
          ready, the isolation audit fails or a required check was skipped.
          Output is unchanged

      --json
          Print machine-readable JSON instead of human text

      --wait <SECONDS>
          With `--ready`, poll every second for up to SECONDS until the instance
          is ready (or the deadline expires)

      --accept-rollback
          Accept a detected store rollback / unknown history / import so the
          next start does not hold older messages, and release the held ones.
          Requires the daemon to be stopped. Messages that were received and
          acknowledged before the rollback cannot be recovered, and frames
          replayed from before the rollback are accepted again within their TTL

  -h, --help
          Print help (see a summary with '-h')

===== agentnet identity rotate-kem --help =====

Add a new encryption subkey (with an expiry); the address stays the same.

The previous subkey is retired (a standard subkey revocation, "key retired") and
keeps decrypting until the retention window ends. At the next `agentnet serve`
the new public certificate is sent to every Trusted contact as a
`contact.update` (they merge it) and their pending messages to you are re-sealed
to the new subkey. With --revoke-previous every earlier subkey is revoked as
compromised and its secret key destroyed at once: messages already sealed to it
are lost unless re-sealed by their senders. There is no forward secrecy against
a later compromise of a subkey you still hold.

Revoked subkeys are kept in the certificate (with their revocation) until they
expire, so the certificate grows; the cap is 8192 bytes, about 21 revoking
rotations per subkey validity period (default 365 days). A rotation that would
exceed it is refused and changes nothing: wait for old subkeys to expire, rotate
without --revoke-previous less often, or create a new identity.
--revoke-previous also destroys the secrets of earlier retained (merely retired)
subkeys. A certificate above about 5 KiB can no longer be advertised
(discovery).

Usage: agentnet identity rotate-kem [OPTIONS]

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --expires-in-days <DAYS>
          Lifetime of the new encryption subkey in days (default 365)

      --json
          Print machine-readable JSON instead of human text

      --keep-hours <HOURS>
          How long the previous key keeps decrypting (default:
          storage.retention_hours)

      --revoke-previous
          Revoke every earlier encryption subkey as compromised and destroy its
          secret key immediately

  -h, --help
          Print help (see a summary with '-h')

===== agentnet identity revoke --help =====

Revoke this identity (the primary key): irreversible for this address.

Creates a standard OpenPGP key revocation, writes it next to the identity (as
the revoked public certificate) and marks the local identity revoked: the daemon
then sends nothing except the revocation notice, which it delivers to every
Trusted contact at the next start. Reaches only contacts that are reachable

===== agentnet identity migrate --help =====

Migrate a data directory written by the retired HPKE + Ed25519 format (`an1`).

Explicit and never automatic (`serve` refuses an old data directory and names
this command). Generates a fresh OpenPGP identity (the old key is not reused; an
`an1` address cannot become an `an2` address), moves the old identity file aside
as `identity.json.legacy-v1`, keeps the inbox history and the dedupe state,
lists every pending old-format outbound message and marks it failed (re-send it
after adding the recipient's new certificate), and keeps old contacts as
unverified legacy entries (not contacts: `an1` addresses are refused as
recipients) until each contact's NEW certificate is added; nothing links it to
the legacy entry, so verify the new address out of band and add it with `contact
add --expect <new address>` (without --expect it is added untrusted). The
retired identity file keeps the OLD SECRET KEYS on disk; the command prints its
path and a warning, delete it once you no longer need it. Prints the new
address. Requires the daemon to be stopped.

Usage: agentnet identity migrate [OPTIONS]

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --json

===== agentnet contact add --help =====

Add a contact from its public OpenPGP certificate, or merge an update into a
known one.

First contact pins the certificate's fingerprint: pass --expect with the address
obtained out of band. Without --expect the contact is added as untrusted (a
warning says how to verify and raise trust) and --trust trusted is refused. An
update for a known address is merged into the stored certificate (new subkeys,
expiry, revocations); it never replaces it. Adding a known untrusted contact
again with a matching --expect raises it to trusted (the output says so); a
blocked contact is never raised and without --expect trust never changes.

Usage: agentnet contact add [OPTIONS] <RECORD>

Arguments:
  <RECORD>
          The certificate (base64url or ASCII armor), `@FILE` to read it from a
          file, or `-` for stdin

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --expect <ADDRESS>
          Require the certificate to be for exactly this address (obtained out
          of band)

      --alias <ALIAS>
          Local nickname

      --json
          Print machine-readable JSON instead of human text

      --trust <TRUST>
          Trust decision (default: trusted with --expect, untrusted without it)
          
          [possible values: trusted, untrusted, blocked]

  -h, --help
          Print help (see a summary with '-h')

===== agentnet discovery advertise --help =====

capabilities, display name, contact record, timing). It is re-published by the
daemon until it expires or is withdrawn.

Usage: agentnet discovery advertise [OPTIONS] --topic <TOPIC> --capability <NAME[:DESCRIPTION]>

Options:
      --data-dir <DIR>
          Data directory (identity, config, database, socket, tokens)
          
          [env: AGENTNET_HOME=]

      --topic <TOPIC>
          Discovery topic name (must be listed in discovery.topics)

      --capability <NAME[:DESCRIPTION]>
          A capability as NAME or NAME:DESCRIPTION (repeatable; name is a-z 0-9
          . _ -)

      --json
          Print machine-readable JSON instead of human text

      --display-name <NAME>
          Optional display name (at most 64 characters)

      --ttl <SECONDS>
          Lifetime in seconds (default and maximum come from agentnet.toml)

  -h, --help
          Print help (see a summary with '-h')
