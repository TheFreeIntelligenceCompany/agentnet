## Tailscale variant (UNTESTED)
UNTESTED - not run on this project's test hosts; reproduce and verify before relying on it.
1. On every machine: `tailscale up`; note the relay's tailnet IPv4 with `tailscale ip -4` (100.x.y.z).
2. Relay node: use the relay flags above but bind and advertise the tailnet address only:
--listen-address=<relay tailnet IP>  --nat=extip:<relay tailnet IP>
(with Docker use `network_mode: host`, otherwise the container cannot see the tailnet interface).
3. Client node: same flags as above with --staticnode/--storenode/--filternode/--lightpushnode =
/ip4/<relay tailnet IP>/tcp/60000/p2p/<relay peer id>, --nat=extip:<client tailnet IP>.
4. agentnet.toml: node_url = "http://127.0.0.1:8645"; peers = ["/ip4/<relay tailnet IP>/tcp/60000/p2p/<relay peer id>"]
(100.64.0.0/10 passes the private-address check).
5. Tailnet ACL: allow only your client nodes (by tag) to reach tcp/60000 on the relay and deny everything else, e.g.
{"acls": [{"action": "accept", "src": ["tag:agentnet-client"], "dst": ["tag:agentnet-relay:60000"]}]}
Tailscale gives encrypted connectivity and machine-level policy only. It is not application identity or message
encryption (AgentNet does that end to end), and its coordination service sees connection metadata.

## Notes
- Flags are the set verified in spike/relay (docs/spike/notes-daemon-rest.md); retention values other than time:3600;capacity:5000 are UNTESTED.
- Generate node keys with `openssl rand -hex 32` (one per node); the relay's peer id is printed in its log and by GET /info on its REST port.
- Start the relay first, then the client node, then `agentnet serve`.
- --dns-addrs-name-server=127.0.0.1 stops the node's online-monitor from querying 1.1.1.1 every 5 s (the only external contact seen with discovery off). On a no-egress network the node may consider itself offline until its first peer connects.
- Cluster ids 1, 2, 3 and 16 select public presets (public bootstrap, RLN) and are rejected by agentnet. Cluster/shard separation is not access control: restrict who can reach tcp/60000 with firewall rules.
- Only run the node REST port on loopback: it has no authentication.
